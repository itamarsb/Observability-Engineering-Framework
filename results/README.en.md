# Results

**Language:** [Português (Brasil)](README.md) | **English (US)**

No experimental results have been published to date. Pilot runs are used only to calibrate parameters and are not presented as results.

## Data organization

| Location | Contents | Version-controlled |
|---|---|---|
| `runs/pilot/`, `runs/campaign/` | One directory per run (`<cenário>-<repetição>-<horário UTC>`): manifest, raw k6 output, probe data, server events, Prometheus, Loki, and Tempo exports, container logs, and `checksums.sha256` | No — kept outside Git, in three copies |
| [`processed/`](processed/) | Consolidated summaries (`summary-*.csv`) generated from analyzed runs | Summaries only |
| [`charts/`](charts/) | Figures generated by plotting scripts | No — regenerated from the data |
| [`evidence-index.csv`](evidence-index.csv) | Traceability index: each piece of evidence, its source file, the script or query that produced it, and where it is used | Yes |

Aborted, invalid, or **not yet reviewed** runs are retained and excluded from consolidation. Each run's classification is recorded in `notes.md` on the line `- Classificacao final: VALIDA`, `INVALIDA`, or `PENDENTE`; only `VALIDA` runs are included in the results.

> **Automation compatibility:** The directory-name placeholders denote the scenario, repetition, and UTC timestamp. The scripts use the original Portuguese classification tokens and field names. `VALIDA` means valid, `INVALIDA` means invalid, `PENDENTE` means pending, and `INCONCLUSIVA` means inconclusive. Do not translate these literal values in run files, command-line arguments, or automation inputs.

## Automated workflow

```bash
# Stage 6 — calibration
scripts/run_ramp.sh                                   # capacity ramp + Figure C10
python3 scripts/calibrar_taxas.py --aplicar           # C0, C2, C3 rates (and R0 for C4–C7) from the ramp
scripts/run_scenario.sh C0 r01 pilot                  # C0 pilot runs (r01, r02, r03)
python3 scripts/derive_slo.py runs/pilot --gravar     # P95/P99 targets -> slo.env and protocol-v1.md

# Stage 8 — campaign (3 blocks × 6 scenarios = 18 runs)
python3 scripts/run_campaign.py --dry-run             # plan, estimated duration, and server check
python3 scripts/run_campaign.py                       # run (or resume)

# Stage 9 — review and results
python3 scripts/revisar_execucoes.py                  # proposes VALIDA / INVALIDA / INCONCLUSIVA
python3 scripts/revisar_execucoes.py --aplicar        # writes to notes.md files (with confirmation)
python3 scripts/gerar_resultados.py                   # consolidates runs and generates figures and tables
```

**Calibration.** `calibrar_taxas.py` defines capacity (Cap) as the highest stable step before the knee point and proposes C0 = R0 = 22.5% of Cap, C2 = 45%, and C3 = 75% (the midpoints of the ranges in the [experimental matrix](../experiments/experimental-matrix.en.md)); perturbation scenarios use R0. It issues a warning when load generator CPU usage indicates that the measured limit may be due to the laptop. `derive_slo.py --gravar` applies the target-setting rule (2 × the median of the C0 pilot runs, rounded up to multiples of 25 ms). Both scripts also update the corresponding rows in the authoritative [`protocol-v1.md`](../experiments/scenarios/protocol-v1.md) ([English reference translation](../experiments/scenarios/protocol-v1.en.md)) and refuse to make any changes after the freeze (`PROTOCOL_VERSION` without `-rascunho`).

**Campaign.** The campaign runner calls `scripts/run_scenario.sh` once per run, observes the minimum interval, and checks that the server is in a stable state before each run (idle CPU usage, available memory, disk space, temperature, Prometheus targets, and stopped stressors), as specified in [`campaign.env`](../experiments/scenarios/campaign.env). A run automatically invalidated due to a technical failure is retained and repeated at the end of the block; a precondition-related abort or `Ctrl+C` interrupts the campaign. To stop safely at the end of the current run, create the file `runs/campaign-logs/PARAR`. To resume, execute the same command.

**Review.** `revisar_execucoes.py` applies the criteria in the protocol's *Validade* (Validity) row, using the limits in [`validade.env`](../experiments/scenarios/validade.env): load (k6, `dropped_iterations`, load generator CPU usage), probe (coverage), telemetry (exports, time series, restarts, and OOM), intervention (events and exit code), and integrity (`checksums.sha256`). A technical failure results in `INVALIDA`; cases requiring judgment (for example, `dropped_iterations > 0`) are classified as `INCONCLUSIVA`, remain `PENDENTE`, and have their reasons recorded in `notes.md` for the operator's decision. Each review writes a report to `runs/campaign-logs/`.

**Results.** `gerar_resultados.py` consolidates valid runs, selects the run with the median ΔP95 for C4, C5, and C6, generates Figure 3, Figure 4, Figures C10, C12, C13, and C14, Tables 2 and 3, Exhibit 3 (Quadro 3), and Tables A1–A3, and writes `results/resultados-<UTC>.md` with the commit, selections, warnings, and SHA-256 of each file. With `--copiar-para <pasta>`, it copies everything to a Windows directory. The individual scripts (`fig_carga.py`, `fig_perturbacao.py`, `fig_rampa.py`, `tabelas_artigo.py`) remain available to generate a single figure.

Each figure has an accompanying `<figura>.png.fonte.json` file containing the script, parameters, and SHA-256 of every input read. Values without valid samples appear as `indef.`, never as zero, and Exhibit 3 (Quadro 3) issues a latency verdict only after the targets have been entered in [`slo.env`](../experiments/scenarios/slo.env).

The integrity of a run directory can be verified with `sha256sum -c checksums.sha256`, executed from within that directory.

## Offline tests

```bash
python3 -m unittest discover -s tests -v
```

The tests use **synthetic** runs generated by [`tests/synthetic_runs.py`](../tests/synthetic_runs.py), in the same format as laboratory runs, to verify review, calibration, analysis, figures, tables, results generation, and the campaign runner without Docker, k6, or a server. Synthetic data is marked in the manifest (`"synthetic": true`) and always produces figures with a watermark and tables with the `SINTETICO_` prefix; there is no option to remove these markings.
